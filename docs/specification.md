# システム仕様

## 店頭での利用

来場者は店頭に並んで注文します。
スタッフが注文を登録し、整理券を渡します。
来場者はWebページや店頭モニターでできあがりを確認し、商品を受け取ります。

利用規模は2日間で約1,000人を想定します。
注文前の来場者もWebページを閲覧できます。
同時閲覧人数は未確定です。

注文と在庫は日付で区切りません。
日付が変わっても、未受け取り注文と確保済みの商品、余剰在庫、整理券番号を引き継ぎます。
注文履歴は全期間をまとめて表示します。

## 味と販売

味は粒あん、カスタード、栗きんとん、いもあん、宇治抹茶あんの5種類です。
スタッフが味ごとに受付中と受付停止を手動で切り替えます。
時間帯による自動切り替えは行いません。
受付を停止しても、受け付け済みの注文と確保済みの商品は保持します。

焼き型は合計20個分です。
焼き上がりは味ごとの数量を指定し、すべての味を同時に作る前提にしません。
焼き上がり登録では0、1、2、5、10、20個を選ぶボタンを用意します。
合計が20個を超える場合は画面に表示し、複数回分のまとめた登録も扱えます。

## スタッフの操作

スタッフ画面では、注文受付、焼き上がり登録、受け渡し完了、キャンセルを扱います。
味ごとの必要数、確保済みの数量、余剰在庫を確認できます。
準備中の注文ごとに、次の焼き上がりで全品が揃う場合は「そろそろできます」、その次以降は「約○分後」と表示し、店頭で近くにいてもらうための案内に使えます。
優先順、注文した味と数量、確保済みの商品、余剰在庫、焼き時間と1回の数量から、全品が揃うまでの目安を算出します。
注文ごとの目安では、次の焼き上がりを0分として、その後に必要な回数分の焼き時間を数えます。

数量は味ごとの数字ボタンで選択します。
注文受付では、よく使う0、1、2、3個をそれぞれ1クリックで設定できます。
ボタンは数量を加算するのではなく、その数字に設定します。
それ以外の数量も、プルダウンや入力欄への文字入力に頼らず、数量ボタンや増減ボタンで指定できるようにします。
選択中の数量を明確に表示します。
焼き上がり登録にも、よく使う数量を選ぶボタンを設けます。

通常操作はキーボードだけでも完了できます。
数量の数字キーによる選択、味の切り替え、登録、画面切り替え、整理券番号による注文検索に対応します。
注文と焼き上がりの登録はEnterキーで確定します。
味の選択は画面内で保持し、数量を選ぶたびに入力欄を探してフォーカスする操作を不要にします。
キーボードとマウスは同じ数量と登録処理を操作します。

登録成功後は数量を初期化し、次の入力を始められる状態に戻します。
登録失敗時は入力を保持し、未送信と送信結果不明を区別します。
受け渡しは一覧からの選択と整理券番号の直接入力に対応し、注文内容を確認して確定します。
キーボードでは`/`で番号欄へ移動し、整理券番号とEnterキーで受け渡しの確認を開きます。
確定後も番号欄にフォーカスを残し、次の番号を続けて入力できます。
Escキーで番号欄を離れ、数量の入力に戻ります。
焼き上がり数の誤入力は在庫の訂正で修正し、準備中の注文への割り当てを再計算します。
受け取り可能な注文の確保分と受け渡し済みの商品を在庫の訂正で巻き戻すことはできません。

## 味ごとの注文順

通常は、焼き上がった商品を同じ味を注文した人の受付順に割り当てます。
先の注文は、ほかの味がまだできていなくても、できた味の必要数を確保します。
後の注文へは、その確保分を除いた数量だけを割り当てます。
一つの注文の全品が揃った時点で、スタッフが受け渡しを確定できます。

| 受付順 | 注文                       | つぶあん1個と栗きんとん1個だけができた場合 |
| ------ | -------------------------- | ------------------------------------------ |
| 1      | つぶあん1個、カスタード1個 | つぶあんを確保し、カスタードを待つ         |
| 2      | つぶあん1個                | 次のつぶあんを待つ                         |
| 3      | 栗きんとん1個              | 受け取り可能                               |

優先指定がない注文どうしは、同じ味の受付順を維持します。
キャンセル時は確保分を解放し、同じ味を待つ注文へ割り当て直します。
優先指定がない場合は受付順に割り当てます。
待ち時間も、この割り当て規則に基づいて算出します。

## 優先して受け渡す

スタッフは、準備中の注文に「優先する」を指定できます。
受付順が後でも、準備中の注文の確保分、余剰在庫、次の焼き上がりから優先して商品を確保します。
整理券番号と元の受付順は変更しません。
優先は注文の全品が揃うまで続き、複数回の焼き上がりにまたがっても維持します。
一部の商品だけを受け渡す操作は設けません。

### 商品の割り当て

受け取り可能になった注文の確保分は維持します。
優先の指定や解除、通常の割り当てでは、一度受け取り可能になった注文を準備中へ戻しません。
準備中の注文の確保分は、優先注文へ回せます。
在庫の減数訂正でも、受け取り可能な注文の確保分は減らしません。
余剰在庫と準備中の注文の確保分で補えない減数訂正は受け付けません。

受け取り可能な注文の確保分を除き、準備中の注文の確保分と余剰在庫を合わせて、味ごとに次の順で割り当て直します。

1. 優先指定された準備中の注文。複数ある場合は、優先を指定した順。
2. 優先指定のない準備中の注文。元の受付順。

指定した時点で割り当て直し、全品が揃えばその場で受け取り可能にします。
キャンセルや保留によって解放された商品も、同じ順で割り当てます。
先の優先注文が必要としない味は、後の注文へ割り当てられます。
優先を重ねて指定しても、優先注文どうしの順番は変えません。
解除後に再指定した場合は、その時点の優先注文の最後に並びます。

後の注文が粒あん1個を待っていて、優先を指定した場合は次のように扱います。

| 先の注文の状況                     | 優先指定したときの割り当て                                                   |
| ---------------------------------- | ---------------------------------------------------------------------------- |
| 粒あん2個のうち1個を確保し、準備中 | その1個を後の注文へ回し、後の注文を受け取り可能にする                        |
| 粒あん1個を確保し、受け取り可能    | 先の注文の確保分と受け取り可能の状態を維持し、後の注文は次の焼き上がりを待つ |

### 解除とほかの操作

全品が揃ったら「受け取り可能」にし、優先指定を自動で解除します。
スタッフが「優先を解除」を選んだ場合は、準備中の注文への割り当てを再計算し、元の受付順で待ちます。
この場合も、受け取り可能になった注文の確保分と状態は維持します。
保留またはキャンセルした場合は、優先指定を解除し、確保分を解放します。
保留から列に戻したときは、元の受付順で待ちます。
再び優先する場合は、スタッフが指定し直します。
受け取り可能、保留中、受け渡し済み、キャンセル済みの注文には優先を指定できません。
優先指定は日付が変わっても維持します。

### 画面と待ち時間

スタッフの注文一覧と整理券番号による検索から、「優先する」「優先を解除」を操作できます。
キーボードでもボタンに移動して操作できます。
優先の指定と解除後は番号欄にフォーカスを戻し、次の注文を続けて検索できます。
指定中の注文は、スタッフ画面で「優先待ち」と表示します。
一覧は、受け取り可能、優先待ち、通常の準備中、保留中の順に表示します。
優先待ちは指定順、それ以外の同じ状態の注文は受付順に並べます。
優先の指定と解除はほかのスタッフ端末にも反映し、同じ操作の再送で指定順を変えません。

来場者画面と店頭モニターでは、全品が揃うまでは「準備中」、揃ったら「受け取り可能」と表示します。
待ち時間の目安は、優先順と維持される確保分を反映して算出します。
来場者画面の個別注文もスタッフ画面と同じ目安を使い、次の焼き上がりで全品が揃う場合は「そろそろできます」、その次以降は「約○分後」と表示します。
優先注文が必要とする味の焼き上がりを保証する表示は行いません。

## 来ない人の注文を保留する

「飛ばす」で注文を保留し、確保していた商品を次の注文へ回します。
注文内容と整理券番号は保持し、保留中の番号は再発行しません。
保留中も、来場者画面と店頭モニターでは「受け取り可能」の表示を維持します。
スタッフ画面では「保留中」と表示します。

本人が来たら「列に戻す」で元の受付順に復帰させます。
商品が揃うまでは、その場で待ってもらいます。
ほかの受け取り可能な注文の確保分は維持し、次の焼き上がりから元の順番で優先します。
在庫の訂正では、誤って登録した商品数に合わせて準備中の注文の確保分を再計算します。

キーボードでは`/`、整理券番号、`.`キーで保留できます。
保留中の番号を入力した場合は、Enterキーで列に戻します。

## 整理券番号

整理券番号は100からの連番です。
999を超えても発行を続け、日付が変わっても番号をリセットしません。
受け取り完了やキャンセルになった番号も再利用しません。
注文の識別には内部IDを使い、Webで個別注文を追跡できます。

## 構成

| 対象       | 構成                                                           |
| ---------- | -------------------------------------------------------------- |
| 配信       | Cloudflare Workers Static Assets                               |
| API        | TypeScriptのCloudflare Worker                                  |
| 永続化     | Cloudflare D1                                                  |
| 画面       | スタッフ、店頭モニター、来場者向け                             |
| 状態の取得 | 定期取得し、同時閲覧人数と必要な反映速度に応じて間隔を設定する |

注文の採番、在庫の割り当て、確保、状態変更を一貫して更新します。
受付と焼き上がり登録には操作IDを付け、同じ操作の再送を重複して反映しません。
スタッフによる更新はサーバー側で認証し、来場者向けの閲覧と権限を分けます。

## 呼び出しの確認

Webページと店頭モニターに受け取り可能な整理券番号を表示します。
準備中は注文の割り当て状況を表し、実際の調理開始を断定する表示は行いません。
待ち時間は味ごとの焼き時間と1回の数量から求める目安です。
最終更新時刻と通信エラーを表示し、通信が切れた状態を最新の情報と区別します。
店頭モニターで番号が表示領域を超える場合は、8秒ごとに表示を送ります。
